# Validation Methodology: Headless Harness, Traces & Frames

This document specifies the validation harness architecture and deterministic verification protocol used to prove fidelity against the original J2ME bytecode.

---

## 1. Harness Architecture (`tools/harness/`)

The harness runs directly on the original J2ME bytecode from `extracted/` using standard Java (JDK 21) without requiring any phone emulator:

1. **MIDP 2.0 / MMAPI Clean-Room Stubs:**
   - `javax.microedition.midlet.MIDlet`: Application lifecycle and property management.
   - `javax.microedition.lcdui.Canvas`: Custom implementation maintaining 240x320 Nokia display coordinates.
   - `javax.microedition.lcdui.Graphics`: Rendering engine backed by Java's `BufferedImage` and `Graphics2D` supporting translation, clipping, anchor calculations, and affine region transforms (`TRANS_MIRROR`, `TRANS_ROT90`, etc.).
   - `javax.microedition.lcdui.Image`: Image loaders with PNG decoders.
   - `javax.microedition.rms.RecordStore`: In-memory persistence mimicking exact RMS behavior.
   - `javax.microedition.media.*`: Event listener tracking sound play requests and looping counts.

2. **Deterministic Time & Clock Control:**
   - In `f.b()`, the original game computes:
     `l = l2 + 70L - System.currentTimeMillis();`
     `if (l > 0L) wait(l);`
   - To make execution instant (10,000 ticks/sec) and perfectly deterministic, `tools.HarnessClassLoader` patches `f.class` on the fly to route calls to `tools.HarnessClk.currentTimeMillis()`.
   - `HarnessClk` returns the tick start timestamp `t`, and when called at the end of the tick returns `t + 70L`. This makes `l2 + 70 - now = 0`, bypassing all thread sleep operations while ensuring identical mathematical timestamps.

3. **PRNG Seeding:**
   - Reflection sets `f.a = new Random(seed)` with an explicit fixed seed before each level load and reset, ensuring identical random numbers across all runs.

## 2. Deterministic Trace Format

Each tick dumps 16 comma-separated state fields to a text line:
```
tick,px,py,vx,vy,state,frame,hp,max_hp,magic,score,cam_x,cam_y,enemy_count,e0_x,e0_y
```

| Column | Field | Meaning |
|---|---|---|
| `tick` | Loop counter | Monotonically increasing tick index |
| `px` | `f.f.d` | Ranger world X coordinate (pixels) |
| `py` | `f.f.e` | Ranger world Y coordinate (pixels) |
| `vx` | `f.f.f` | Ranger horizontal velocity |
| `vy` | `f.f.g` | Ranger vertical velocity |
| `state` | `f.f.t` | Ranger action state (0=idle, 1=walk, 2=jump up, 3=fall, 4=crouch, 5=attack) |
| `frame` | `f.f.x` | Active animation frame index |
| `hp` | `f.f.z` | Current Ranger Health Points |
| `max_hp` | `f.f.A` | Maximum Ranger Health Points |
| `magic` | `f.an` | Magic Power gauge (0..320) |
| `score` | `g.g` | Cumulative score |
| `cam_x` | `f.ac` | Smooth camera focus X coordinate |
| `cam_y` | `f.ad` | Smooth camera focus Y coordinate |
| `enemy_count`| `f.g.length`| Active enemies count in level |
| `e0_x` | `f.g[0].d` | Enemy 0 world X coordinate |
| `e0_y` | `f.g[0].e` | Enemy 0 world Y coordinate |

## 3. Reference Trace Sets

1. **`traces/idle_level1.txt`**: 100 ticks with no player input; verifies initial entity physics, gravity settling, and idle animations.
2. **`traces/movement_level1.txt`**: 150 ticks with right running, jumping, left running, and crouching.
3. **`traces/combat_level1.txt`**: 200 ticks with combo attacks, jump slashes, and enemy contact.
4. **`traces/survival_level1.txt`**: 150 ticks in survival mode verifying wave spawns.

All reference traces are generated by `tools/record_traces.sh` / `tools/record_traces.ps1` and verified bit-identical on repeated runs (`diff` is empty).
